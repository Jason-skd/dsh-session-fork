- 用分支合并这个小杠杆解决了并行开发问题
- 分支合并模型天生适合并行开发场景，因为他镜像了人类在并行开发时的同步策略（git branch）。人类在并行开发时不需要每个 commit 都停下来处理冲突，而是在各自的 branch 上演进，最后 merge/rebase 到同一个分支上。即便历史要求线形，但是分支合并提供了并行 => 线形这个映射的方案。
- 它不是 sub agent: 它不是为了一个大任务而派发出几个小 agent。它为了让程序员能同时解决好几项几乎不相关的大任务。它也不应该和 sub agent 冲突，虽然我们致力于取代现有的 sub agent 模型，但是小任务的确应该交给 sub agent 来做，更节省上下文也更轻量。选择 branch 能够提供更少的歧义。
- 最实用的点是解决了那个调侃：vibe coding = 聊一句刷十分钟手机。它让你原本要用来刷手机的时间能够持续思考。我实际体验：用 5 倍的 token 消耗量提升了 4 倍的效率。
- 但是 session 的管理比 sub agent 的管理难上许多，它不绑定主 session，生命周期和身份识别更难控制。于是我们先是提供了整套 branch 管理命令，又为所有命令都提供了 tool 版本，配合我们推荐的治理方案，让用户无需顾虑 session 的管理，AI 会做好一切。
- 它能和 `dsh` 所有的功能完美集成，得益于我贯彻始终的模式模仿+vendor哲学。我们的 `squash` 产生的总结消息依然被认作和 `compact` 等价的总结消息；sub agent 依然可以与我们的生态结合。
- 它也有开创“AI 秘书“的潜力：由一个 root branch 维持看板和干净的上下文，秘书会整理你的所有习惯，秘书有和开发者等价的权力，秘书只关心开发者的当前任务的编排和对接。
